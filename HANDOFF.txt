== หลักที่ได้ผลแล้ว (ใช้ซ้ำ) ==
- ทะเบียนเกม: *(base+0x23E6318) = singleton -> hash table 23,805 รายการ (คีย์สตริง -> ตัวชี้เรคอร์ด) ; หาตำแหน่งด้วยชื่อคีย์แทนการค้นค่า (รายละเอียด FACTS ## ทะเบียน)
- ขั้นตอนมาตรฐาน: (1) เขียน probe อ่านอย่างเดียว -> (2) ผู้ใช้รันส่ง .txt -> (3) วิเคราะห์จากไฟล์จริง (ไม่เดา) -> (4) แก้สคริปต์ผู้ใช้เฉพาะจุด + ตรวจซ้ำด้วยตัวที่ได้จากทะเบียน
- ทางเลือกใหม่เมื่อ probe ในเกมตัน: ค้น strings.tsv ของ libsimcity หาสตริงที่เกี่ยวข้อง -> ดูว่าฟังก์ชันไหนอ้างถึง (คอลัมน์ "ฟังก์ชันที่อ้าง") -> เพิ่ม @0xOFFSET ใน keywords.txt -> รัน Action (cache เดิม เร็ว) -> อ่าน decompiled.c ตรงๆ
- ใช้ลายนิ้วมือ/ID/ชื่อคีย์ยืนยันทุกครั้ง เพราะ offset เปลี่ยนตามเวอร์ชันเกม ; บันทึกเวอร์ชันเกมคู่ผลเสมอ

== สถานะงาน (แก้บรรทัดเดิม ไม่ต่อท้ายเป็นประวัติ) ==

[เสร็จ+ทดสอบแล้ว] Change Production Time แบบทะเบียน (11 วัตถุดิบ / สินค้าอื่น / restore) ; เก่า = runChangProductionTimeLegacy
[เขียนแล้ว ยังไม่มีผลทดสอบยืนยัน] Change Products In Factory (11 ช่อง) Registry Search = findSharedSlotsRegistry() เมนูข้อ 3 "Registry Search(stable)"
[ค้าง รอถามผู้ใช้] autoSetFactoryTime1Min() (flow Mayor Pass) ยังใช้การค้น preset เดิม แก้โดนสินค้าอื่นที่เวลาเท่ากันได้ ; ถามก่อนว่าจะเปลี่ยนเป็นแบบทะเบียนไหม และตั้งเฉพาะ 11 วัตถุดิบหรือรวมอื่น

[ยังไม่ทำ] เพิ่มรายการ "ไอเท็มที่เปลี่ยนได้" จากทะเบียน (ต้องมี probe เดินทะเบียนครบ + อ่าน +0x10 ก่อน) ; findMoreItemValues ยังค้นทีละตัว
[ยังไม่ทำ] Vu Pass (ผู้ใช้ยังไม่ระบุว่าเป้าหมายคือค่าไหน; ไม่รวมการเปิดใช้ pass ที่ต้องซื้อ)

== Product Quantity: สถานะ (แก้ในที่เดิม) ==
ทางตันเดิม (ยืนยันแล้ว ไม่ต้องขุดต่อทางนี้): "1" ที่สคริปต์แก้ = ฟิลด์ N-8 ของโหนดแมป ไอดี->เรคอร์ด มีกับทุกไอเท็ม (ไม่ใช่เฉพาะ *Prod) ; เรคอร์ด *Prod เอง (+0xA8=เวลาผลิต, +0x240=XP) ก็ไม่เห็นฟิลด์จำนวนผลิตในคอลัมน์ที่เคยดัมพ์ ; ยังไม่รู้ว่าฟีเจอร์เดิมที่ผู้ใช้บอกว่า "ใช้ได้" จริงๆแก้ถูกวัตถุดิบตัวไหน
เจอใหม่ 2026-10-24 (จาก strings.tsv libsimcity, ยังไม่ถอดรหัส): สตริง ItemQtyMin/ItemQtyMax อ้างโดยฟังก์ชันเดียว 0x8ed2a0 (3648B) ; ปุ่ม BTN_INVENTORY_INCREASE/DECREASE_QUANTITY อ้างโดย 0x8fa7ec(280B)/0x8eff54(1936B)/0x8ee1c4(3148B) — นี่คือโค้ด UI ตัวเลือกจำนวนจริงในเกม ยังไม่ยืนยันว่าเป็นหน้าโรงงานหรือหน้า Trade/Inventory
แผนต่อไป (แทนขุด byte): เพิ่ม 4 ที่อยู่นี้ใน keywords.txt (ส่งไฟล์ใหม่ให้แล้ว) -> ผู้ใช้แทนที่ scre-at/keywords.txt ในรีโป -> รัน GitHub Actions (cache project เดิม ไม่วิเคราะห์ใหม่ เร็ว) -> ส่ง libsimcity/decompiled.c กลับ (ไฟล์เล็ก อ่านเต็มได้) -> อ่านโค้ด C หา offset จำนวนผลิตตรงๆ
ถ้าโค้ดชี้ว่าเป็นหน้า Trade/Inventory ไม่ใช่โรงงาน: ดู callers.tsv ของ 0x8ed2a0 ไล่ย้อนว่าใครเรียก เพื่อหาทางเข้าหน้าโรงงานแทน
ห้ามแก้ findProductQuantityAddresses ในสคริปต์ผู้ใช้จนกว่าจะเห็นโค้ด decompile ยืนยันออฟเซ็ต
